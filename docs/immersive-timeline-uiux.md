# Immersive Timeline UI/UX 设计文档

## 1. 核心概念

Now 时间线的时间线页不是普通列表，也不是任务管理器。

它的核心体验是：

> 用户不是点击按钮添加内容，而是在时间线上点击一个当下锚点，把这一刻钉进时间线。

关键词：

- 全屏
- 时间宇宙
- 当下锚点
- 磨砂玻璃浮层
- 内容从时间点旁边生长出来
- 事件被钉入时间线

本阶段先只做 **桌面端时间线页** 的整体效果验证，不考虑移动端。

---

## 2. 页面第一眼

用户进入 `/timeline` 后，第一眼看到的是一个全屏沉浸式时间场。

不要出现传统后台页面感：

- 不要普通顶部大标题 + 表单 + 列表
- 不要像管理系统
- 不要像 Todo App
- 不要把添加入口做成普通按钮

推荐视觉：

```txt
深色 / 宇宙粒子背景

        ·
        │
        │
     ✦  ●  ← Now Anchor / 当下锚点
        │
        │
        ·

底部悬浮 Dock 只做导航
```

页面主角是一根独立的时间线。

---

## 3. 时间线形态

时间线可以是：

- 纵向中心线
- 微微发光的细线
- 星轨 / 时间流质感
- 线周围有轻微粒子漂浮

本阶段不要求复杂 3D，不要求真实物理粒子。

可以使用：

- CSS radial-gradient
- pseudo elements
- box-shadow / blur
- 少量 absolute 星点
- CSS animation

目标是先看整体氛围，不要为了炫技引入重型依赖。

---

## 4. Now Anchor：当下锚点

时间线上的核心交互点叫：

```txt
Now Anchor / 当下锚点
```

它代表当前时间，而不是今天。

### 状态

默认状态：

- 在时间线中部或偏上位置
- 微微脉冲闪烁
- 有细小光晕
- 鼠标 hover 时亮度增加

首次 / 空状态引导文案：

```txt
点击当下，把这一刻钉住
```

或更短：

```txt
点击当下。
```

禁止文案：

```txt
今天发生了什么？
```

正确文案应围绕：

```txt
当下发生了什么？
这一刻发生了什么？
把这一刻钉住。
```

---

## 5. 添加时间线节点交互

### 5.1 触发

用户点击 Now Anchor。

不要通过 Dock 中央加号作为主创建入口。
Dock 只承担导航，不承担时间线页主输入。

### 5.2 第一步：Glass Time Picker

点击 Now Anchor 后，从时间线锚点旁边浮出一个磨砂玻璃时间卡片。

它应该像是从时间线上长出来，而不是屏幕中央弹窗。

内容：

```txt
当前时间
YYYY.MM.DD HH:mm

[现在] [微调时间]
```

默认时间：

```txt
当前日期 + 当前时刻
```

注意：

- 默认是当下，不是当天 00:00
- 用户可以轻量修改时间
- 如果本阶段不做复杂 time picker，可以先提供 datetime-local input
- 视觉上仍应包装成 Glass UI，而不是浏览器原生表单裸奔

### 5.3 第二步：内容输入浮卡

选择 / 确认时间后，时间卡旁边出现内容输入浮卡。

文案：

```txt
当下发生了什么？
```

输入区：

```txt
[ 当下发生了什么？ ]
[ 钉入时间线 ]
```

保存后：

- 调用已有 timeline 创建逻辑
- 创建 `TimelineNode`
- `happenedAt` 使用选择的时间
- `dayId/date` 仍然来自当前 `DayWorkspace`
- 节点出现在时间线上

---

## 6. 生成反馈

保存成功后：

- 输入浮卡收缩 / 淡出
- 时间线上生成一个新节点
- 节点短暂发光
- 背景粒子轻微向节点聚拢或闪烁
- 内容卡片贴在线旁边

体验隐喻：

> 这一刻被钉进时间线。

不需要大烟花，不需要粒子爆炸。

---

## 7. 已有节点展示

已有时间线节点不应只是普通列表卡片。

它们应该围绕时间线排列：

- 节点光点在线上
- 内容卡片浮在线侧
- 时间显示靠近节点
- 节点之间有时间流动感

桌面端可以采用左右交错：

```txt
[内容卡片] ─ ●
              │
              ● ─ [内容卡片]
              │
[内容卡片] ─ ●
```

如果实现成本较高，本阶段可以先统一放右侧，但必须保留“节点挂在线上”的感觉。

---

## 8. 删除交互

删除不常驻显示。

交互：

1. 点击已有内容卡片
2. 卡片进入 active 状态
3. 右上角浮出一个小 `×`
4. 点击 `×` 删除该节点
5. 节点光点熄灭 / 卡片淡出

删除按钮不要一直显示，否则会破坏沉浸感。

本阶段可以先不做复杂确认。
后续可加 undo toast。

---

## 9. 底部 Dock

本阶段 Dock 只做导航，不做主输入。

Dock 可以包含：

```txt
首页 / 时间线 / 画布
```

要求：

- 固定底部居中
- 毛玻璃
- 当前页面高亮
- 不抢 Now Anchor 的主视觉

Dock 是空间切换器，不是创建入口。

---

## 10. 本阶段边界

Task 6 只做桌面端时间线页效果。

明确不做：

- 移动端适配
- 画布页重做
- AI 报告
- 后端
- 同步
- 账号系统
- 完整 PWA 全屏发布
- 复杂 3D 粒子引擎
- 大规模业务逻辑重构

可以动：

- `TimelinePage`
- `TimelineView`
- timeline 相关组件
- layout / Dock 外壳
- styles / theme
- 少量 UI 组件

不要动：

- Dexie schema
- repository 语义
- Daily Workspace 模型
- Todo 完成闭环
- timeline service 的核心数据语义

---

## 11. 设计验收

本阶段验收重点不是功能数量，而是第一眼是否成立。

验收问题：

1. 打开 `/timeline`，是否第一眼就是全屏时间线，而不是普通列表页？
2. Now Anchor 是否明确、可点击、有引导？
3. 创建节点是否像“从时间点生长出来”？
4. 文案是否使用“当下”，而不是“今天”？
5. 新节点是否被钉在线上，而不是追加到普通列表？
6. 删除是否隐藏在 active 状态里，而不是常驻管理按钮？
7. Dock 是否只是导航，不抢创建入口？
8. 原有 timeline 数据是否仍可正常读取 / 创建 / 删除？
